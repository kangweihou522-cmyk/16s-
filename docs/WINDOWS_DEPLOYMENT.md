# Windows 自选目录部署（方案 A）

Windows 负责选择目录、桌面入口和下载更新；现有 WSL Ubuntu 与 Conda 继续执行分析。此部署不迁移 WSL、Conda、系统账户或已有数据，不安装 Docker，也不重装 QIIME/R。

## 首次部署

1. 完成或取消正在运行的分析，在旧 Ubuntu 工作站窗口按 `Ctrl+C` 停止服务。旧源码、环境和结果保留。
2. 从 [GitHub 下载完整源码 ZIP](https://github.com/kangweihou522-cmyk/16s-/archive/refs/heads/main.zip)，全部解压到任意文件夹。
3. 双击 **部署工作站.bat**，选择安装目录。默认 `D:\16S分析工作站`，也可选 E 盘等其他文件夹。不要在 ZIP 内直接运行单个脚本。
4. 启动器自动选择已安装的 Ubuntu，记录其现有用户，检测该用户的 Conda。缺少 Conda 时停止；缺少某个分析环境时列出名称，网页仍可打开，但对应分析须先准备好该环境。
5. 成功后打开浏览器并创建桌面“16S分析工作站”快捷方式。默认地址 `http://localhost:8766`；转录组工作站可继续使用 8767。

首次部署不会自动关闭没有新服务标识的旧工作站。若提示端口被占用，先在旧窗口停止服务，再重试。启动器不会终止不认识的进程。

## 以后如何使用

- **启动工作站.bat**：唤起 WSL，使用本机已部署版本，打开浏览器；不联网检查更新。已启动的同一工作站直接打开已有页面。保持弹出的服务窗口运行。
- **更新工作站.bat**：检查任务状态，由 Windows 通过 HTTPS 下载 GitHub main 源码，记录 SHA256，检查 ZIP 路径，在独立程序目录准备并检查候选版本，成功后切换、启动。任务运行中拒绝更新。下载或候选检查失败保留原版本；新版本启动失败会尝试恢复原配置和入口，错误保存在日志中。
- **检查环境.bat**：显示安装位置、当前程序、WSL 用户、Conda 及各分析环境是否存在；不安装依赖，不修改环境。
- **停止工作站.bat**：只停止这个安装目录所属的空闲服务。分析运行中先在网页完成或取消任务，不会强行中断分析。

更新不删除旧程序目录，不覆盖修改过的版本或根目录启动脚本，不改原始数据和分析结果。已有目录中若有不同内容的入口，部署会停止并保留它，提示用户处理。

## 位置与配置

| 默认位置 | 内容 |
|---|---|
| `D:\16S分析工作站\程序\版本摘要\` | 每次独立保存的源码及来源清单 |
| `原始数据\` | 可选的数据存放位置；仍可从网页选择原来的任意数据目录 |
| `参考文件\` | 可选的分类器、KO 注释映射等存放位置 |
| `分析结果\` | 新部署的默认输出根目录，每个分析继续创建独立 run |
| `配置\workstation.json` | 实际目录、Ubuntu、用户、端口、Conda 和环境名 |
| `日志\server.log` | 服务输出日志 |
| `日志\wsl-launcher.log` | Windows/WSL 调用阶段、退出码和错误 |
| `日志\updates\` | 更新源码归档、SHA256 与部署计划 |

网页顶部显示安装目录、程序版本目录与默认结果目录。刷新/重新打开默认空白批次，清空旧输入和结果关联，输出目录恢复为部署默认位置；环境与作图偏好保留。后台任务在左侧“任务进度”查看，不自动回填旧路径。旧结果用“打开历史批次”明确选择原run，失败任务可检查恢复边界后继续；这不会搬迁旧结果。

默认分析环境为：

| 用途 | 环境名 |
|---|---|
| QIIME 2 | `qiime2-amplicon-2025.7` |
| R 绘图 | `16s-workstation-r` |
| ANCOM-BC2 | `16s-workstation-ancom` |
| LEfSe | `lefse` |
| PICRUSt2 | `picrust2` |

网页环境名仍可编辑。要调整安装级默认值，在停止服务后编辑 `配置\workstation.json` 的 `conda_wsl` 或 `envs`，保持路径、service_id 等身份字段不变，然后重新启动。环境名修改不执行任何安装。

## 网络与高级选项

日常启动离线可用。更新默认使用 Windows 系统代理，包括系统配置的代理自动发现。如果需要指定代理，可在安装目录新建 `配置\download.json`：

```json
{"proxy":"http://127.0.0.1:10808"}
```

使用 `{"proxy":"direct"}` 表示直接连接；不要在文件中放代理密码。下载保留 TLS 校验，网络失败时使用当前安装版本。

源码更新直接从 GitHub 的 `codeload.github.com` 下载，最多3次尝试共享180秒下载预算，显示进度；连接/单次读取最长30秒。每次重试使用独立临时文件，残缺文件不作为源码；下载成功并检查后才进入候选版本准备，不会因下载失败停止旧服务。

若旧版更新器显示“使用3个参数调用Read…操作已超时”，这发生在源码下载阶段，旧程序和结果仍在。旧更新器无法自动获得自己的下载修复；可先用“启动工作站.bat”继续工作。一次性修复可下载最新版 `windows/Workstation.ps1` 后在Windows PowerShell以`-Action Update`运行，并选择原安装目录；或在浏览器下载[完整源码ZIP（直接下载）](https://codeload.github.com/kangweihou522-cmyk/16s-/zip/refs/heads/main)，解压后运行其中的`部署工作站.bat`，选择**原安装目录**完成本地源码更新。无需重装WSL/Conda或移动分析结果。

也可从解压目录的 PowerShell 明确指定初次部署参数：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\windows\Workstation.ps1 -Action Install -InstallRoot 'E:\16S分析工作站' -Distro Ubuntu-24.04 -Port 8766
```

脚本参考同一作者的 [H- 转录组工作站部署层](https://github.com/kangweihou522-cmyk/H-/tree/main/windows)，针对 16S 的 Conda、现有历史结果和任务状态进行适配。部署与服务管理使用 Python 标准库；实际 Windows WSL 桥接、目录选择窗口和桌面快捷方式仍需以本机执行结果确认。
